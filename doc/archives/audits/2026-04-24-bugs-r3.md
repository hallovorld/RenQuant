## 1. Panel training pipeline — `pp_panel_training.py`

### R3-#1 🟡 `LabelsTask` overwrites `panel["date"]` to_datetime after merge
- `panel = panel.merge(raw_df, on=["ticker", "date"], ...)` then later code
  treats `panel["date"]` as `datetime64`. Pandas merge returns object-dtype
  if either side is object — defensive coerce missing.

### R3-#2 🟡 `BuildPanelTask` group_sizes computed before merge with `raw_residuals`
- Line 941: `group_sizes = panel.groupby("date").size()`
- Line 956: `panel = panel.merge(raw_df, ...)`
- Pandas `merge(how="left")` _usually_ preserves left-frame order, but the
  invariant is fragile: future pandas versions could reorder, then
  `group_sizes` and `panel` row order desync.

### R3-#3 🟡 CrossValidateTask transformer adapter captures outer `panel` by reference
- `_SklearnAdapter.fit/predict` reads `panel.loc[X.index, "date"]`. If the
  parent task ever mutates `ctx.panel` between CV and fit, predictions silently
  use stale dates. Today's flow doesn't trigger it; brittle.

### R3-#4 🟡 LightGBM/XGBoost CV adapter `predict()` doesn't attach `date`
- The transformer adapter explicitly sets `df["date"] = panel.loc[X.index, "date"]`.
  The lightgbm/xgboost ones just `return self._m.predict(X.copy()).values`. If
  any backend ever needs the date for grouping, the contract breaks silently.

### R3-#5 🟡 `_SklearnAdapter` per-bar `predict_distribution` doesn't normalize NaN
- See R3-#7 below — feeds raw X to xgboost/lgbm that handle NaN; transformer
  goes through `_build_date_groups` which does `np.nan_to_num`. Inconsistent.

### R3-#6 🟡 Multiple `try/except Exception` in TickerPanelFeatureJob /
   TickerPanelNeutralizeJob / TickerPanelFactorJob silently swallow errors
- Failures produce empty frames but downstream callers (PanelFeatureJob)
  log only counts. A genuine bug in factor computation can disappear with
  one log line.

### R3-#7 🟡 `_SklearnAdapter._final_fit` uses `xgb_params` from outer scope
- Same closure pattern as #3. Same fragility.

### R3-#8 🟡 `SaveArtifactTask` reads `ctx.cv_result["mean_ic"]` without null guard
- If CrossValidate failed silently and `ctx.cv_result is None`, KeyError on save.

## 2. Panel models — `ltr_model.py`, `lgbm_ltr.py`, `transformer_model.py`

### R3-#9 🟡 `PanelLTRModel.train` `early_stopping_rounds` parameter is ignored
- Signature accepts `early_stopping_rounds: int | None = 50` but the function
  hardcodes `early_stopping_rounds=None` and `evals=None` in `xgb.train`.
  Tests / callers passing the param see no effect. Misleading API.

### R3-#10 🟡 `PanelLTRModel` `eval_panel`/`eval_group_sizes` only used post-train
- Same as #9 — accepted as parameters, plumbed only into post-fit IC, never
  into `xgb.train`'s native eval/early-stopping. Documented as such would be
  fine; current shape suggests early-stop is wired when it isn't.

### R3-#11 🟡 `PanelLTRModel.train` row→group weight aggregation produces
   NaN with empty groups
- Line 113: `w_rows[offset:offset+gs].mean()`. If any `gs == 0` (shouldn't
  happen but no defensive check), `.mean()` warns and returns NaN. XGBoost
  then treats NaN weight per group → degenerate ranking.

### R3-#12 🟡 `PanelLTRModel.train` monotone constraint string format is XGBoost-pre-2.0
- `"(s1,s2,...)"` string. Newer XGBoost wants a `dict[str, int]` or `list`.
  Hard-coupled to a specific xgboost version range.

### R3-#13 🟡 `lgbm_ltr._bucketize_labels` returns all-zero array when n < n_buckets
- `if len(y) < n_buckets: return out` (out is zeros). Tiny panels become
  monolithic buckets, training silently learns nothing. Should warn.

### R3-#14 🟠 `PanelTransformerModel.load` `torch.load(pt_path, map_location=...)`
   uses default `weights_only=False`
- Security: arbitrary code execution if loading a malicious .pt. Future-proof:
  PyTorch 2.6 made `weights_only=True` the default and may make `False`
  raise. **Set `weights_only=True` explicitly.**

### R3-#15 🟡 `PanelTransformerModel` `noise = torch.randn_like(yb)` not seeded
   via `gen`
- `_seed_everything(seed)` controls global torch seed but each forward
  pass's `randn_like` uses the device's default RNG. Re-runs with same
  seed should be identical; in practice MPS doesn't honour torch.manual_seed
  for randn_like predictably.

### R3-#16 🟡 `PanelTransformerModel.train` no-eval branch leaves `best_iter=None`
- After early-stop guard skipped, `self.best_iter` stays the `__init__`
  default (None). Save artifact records None.

### R3-#17 🟡 `_safe_div` returns NaN on division-by-zero, but `vol_ratio` then
   propagates NaN through the row's z-score
- Acceptable, but the `compute_hourly_features` description claims
  "first-hour volume" — a value of zero is a real signal (no trading), not
  necessarily a NaN. Subtle.

### R3-#18 🟡 `compute_hourly_features` hardcodes "America/New_York"
- Line 132. If we ever fetch foreign tickers, this breaks. Should read
  exchange tz from a per-ticker map.

## 3. Panel pipeline scorers — `kernel/panel_pipeline/`

### R3-#19 🟠 `PanelScorer.load` `xgb.Booster.load_model(bytearray(...))` —
   booster JSON loader does not validate signature/structure
- Loading a tampered artifact silently produces a different model. Defensive:
  hash + verify before load. Low risk in single-user environment.

### R3-#20 🟠 `EnsemblePanelScorer.score` keys lookups by scorer's `feature_cols`
   — KeyError on missing column
- `feature_matrix[list(s.feature_cols)]` raises if the matrix doesn't carry
  every column. The constructor builds `feature_cols` as a UNION across
  scorers, but `BuildFeatureMatrixTask` builds the matrix from ONE scorer's
  feature list (`scorer.feature_cols`). Ensemble scorer needs every union
  column; mismatch → runtime KeyError mid-bar.

### R3-#21 🟡 `feature_matrix._pick_today_row` mixes tz-aware vs naive `today`
- `idx = pd.to_datetime(df.index)` preserves the source tz. Comparison
  `idx <= today` raises TypeError when one is tz-aware and the other isn't.
  Live runner path passes a date; sim adapter passes a Timestamp without tz —
  works today but fragile.

### R3-#22 🟡 `TransformerPanelScorer.score` fabricates `frame["date"] = 0`
- Treats the inference matrix as a single date-group via a constant date
  column. If any caller passes a multi-date matrix to a TransformerPanelScorer,
  predictions blend across dates instead of grouping. Should assert
  `len(set(dates)) == 1`.

## 4. Training models — `training/models.py`, `training/tournament.py`

### R3-#23 🔴 `tournament._seed = abs(hash(ticker)) % (2**32)` — non-deterministic
- Python's built-in `hash()` is salted by `PYTHONHASHSEED` (random by default).
  So `hash("AAPL")` differs between runs → seed differs → "reproducible"
  models aren't reproducible. **Use `hashlib.md5(ticker.encode()).digest()`
  for a stable hash.**

### R3-#24 🟡 `XGBoostModel.train` passes `use_label_encoder=False` (deprecated)
- xgboost 1.7+ removed this kwarg; xgboost 2.x raises TypeError. Pin xgboost
  version OR drop the kwarg.

### R3-#25 🟡 `XGBoostModel.predict_bulk` thresholds with `score < -self.sell_threshold`
- With `sell_threshold = 0.55` (positive), gate is `score < -0.55`. Works.
  But if user ever sets `sell_threshold = -0.55` (negative), gate becomes
  `score < 0.55` — a very loose sell criterion. Sign-coupling is unstated.

### R3-#26 🟡 `ClassificationModel.train` shifts features by 1 bar
- Trains on `(features[t-1] → label_t)` but inference uses `features[t]` →
  effectively predicts `label[t+1]` — off-by-one in horizon. Pre-existing
  pattern, common in finance ML, but worth documenting.

### R3-#27 🟡 `tournament.run_tournament` line 200 hardcodes `feature_cols[:5]`
- Q-Learner uses the first 5 features regardless of model_params content.
  Magic number; if `feature_columns` order changes, Q-Learner silently
  consumes different inputs.

### R3-#28 🟡 `tournament.run_tournament_all` mutates `os.environ["PYTHONPATH"]`
- Sets env var as a side effect to support spawn-based ProcessPoolExecutor.
  Persists for the rest of the process lifetime.

### R3-#29 🟡 `_evaluate` returns `(metric, sh)` tuple via Python ternary
   precedence trick — readable as bug to a reader
- `return ic if winner_metric == "ic" else sh, sh` parses correctly but
  many readers will parse it as `return ic if cond else (sh, sh)` and assume
  bug. Wrap in explicit parens `((ic if ... else sh), sh)`.

### R3-#30 🟡 `XGBoostModel.train` line 446 `sell_ratio` divides by zero-protected
   denom but produces useless scale_pos_weight when no positives exist
- 0 positive labels → `scale_pos_weight = N_negatives / 1 = N`. Trains then
  predicts ~all-negative. Caller expects "model just doesn't fire" but
  XGBoost still imposes overhead. Defensive: skip training when `(y==1).sum() < 5`.

## 6. Kernel utility modules — `earnings_surprise.py`, `fundamentals.py`

### R3-#35 🔴 `kernel/earnings_surprise.compute_earnings_surprise_cum` lookahead bias
- Line 192-193:
  ```python
  trailing = sp.rolling(trailing_quarters, min_periods=1).sum()
  daily    = trailing.reindex(idx, method="ffill")
  ```
  The trailing sum INCLUDES the just-announced row. Then ffill onto the
  daily index makes the announcement DATE itself carry the new cumulative
  value. If the announcement is after market close (typical), the model
  on that bar uses the NEW value before it was knowable — **lookahead leak**.
  Fix: shift the trailing series by one bar before reindex.

### R3-#36 🟠 `kernel/earnings_surprise.fetch_earnings_surprise` cache never refreshes
- Line 123-126: `if cached is not None and not cached.empty: return cached`.
  Same pattern as `kernel/insider_trades.fetch_insider_trades` (audit R2-#26).
  New earnings announcements posted after the first cache write are invisible.

### R3-#37 🟠 `kernel/fundamentals.fetch_fundamentals` cache never refreshes

  write.

### R3-#38 🟡 `kernel/earnings_surprise._fetch_from_yfinance` line 94

### R3-#39 🟡 `kernel/insider_trades.ticker_to_cik` global `_CIK_MAP`

### R3-#40 🟡 `kernel/insider_trades._USER_AGENT` hardcoded with personal email

### R3-#41 🟡 `kernel/insider_trades._parse_form4_xml` regex on XML

### R3-#42 🟡 `kernel/fundamentals._latest_non_nan` assumes most-recent-first row order

### R3-#43 🟡 `kernel/fundamentals.book_to_price` from `1/p2b` propagates negative
