### #1 — `kernel/exits.py` σ-aware stop_loss (Fix #0a) — 🔴 RED, dead code

**Claim:** "σ-aware stop_loss widens threshold for high-vol stocks → fewer false exits → +0.5 pp APY est."

**What I read:**
- `kernel/exits.py:450` — `if stop_n_sigma > 0: sigma = getattr(state, "sigma", None); if sigma is None ... return; sigma_threshold = stop_n_sigma * daily_vol`
- `kernel/exits.py:299-301` — same σ guard in `check_profit_ladder`

**Where `state.sigma` gets WRITTEN (production data flow):**
- `grep -rn "hs\.sigma" backtesting/renquant_104/ --include="*.py"`:
  - **ONE** prod write site: `kernel/panel_pipeline/job_panel_scoring.py:1053` inside `ApplyNGBoostTask`
  - That task is **gated by `panel_ngboost.enabled`** which is **`false` in `strategy_config.json`** (per CLAUDE.md "NGBoost OFF baseline").
  - Sim adapter never sets `hs.sigma` directly; it only constructs `HoldingState(entry_price, entry_date, high_watermark, prev_close, shares)` at `adapters/sim.py:788` — leaves `sigma` as the dataclass default `None`.

**Evidence the code path didn't execute (ablation log):**
- baseline 252 trades / -5.31% APY / -0.16 Sharpe
- fix_0a 252 trades / -5.31% APY / -0.16 Sharpe — **bit-identical**
- For the σ-aware threshold to widen from 5% (regime fixed-stop) to anything, σ must be > 0; with σ=None the `if sigma is None: return` short-circuits and falls through to the legacy fixed-% path

**Why my tests passed:** all 18 unit + 12 e2e tests build `HoldingState(sigma=0.10|0.30)` manually. Production sim builds `HoldingState(...)` without sigma → defaults to None → my code skips silently.

**Verdict:** Fix #0a is dead code in current production config. Either:
1. Re-enable NGBoost (already rejected in 27-mo A/B per E55, -3.78 APY)
2. Add a `state.sigma` fallback computed from a rolling-vol estimator that runs without NGBoost
3. Revert Fix #0a — it cannot fire as designed

Same diagnosis applies verbatim to **Fix #0c (profit ladder)**.

**Action needed:** revert these two fixes from `exits.py` OR wire a non-NGB σ source. Will recommend revert below.

### #2 — `kernel/exits.py` time-decayed stop tightening (Fix #0b) — 🔴 RED, actively harmful

**Claim:** "After N days held, tighten stop. Catches bleeders model said-exit-but-stop-not-yet."

**What I read:**
- `kernel/exits.py:460-467` — uses `state.hold_days` (independent of σ)
- `compute_exits` at line 686-690 computes `state.hold_days = (today - state.entry_date).days`
- `state.entry_date` IS populated by sim adapter at `adapters/sim.py:790` → ✅ field flows
- Math is correct: linear decay from 1.0× to floor (0.4) over [decay_days, 2×decay_days]

**Why it's still RED:** ablation result is direct — **−4.33 pp APY / −0.20 Sharpe** with **+23 more trades**. The fix DID fire (unlike #0a/#0c) but **made things worse**: in BULL_VOLATILE the tighter-over-time stop fires on noise-day pullbacks instead of real broken theses. The hypothesis (Schwager 1992 / Lo 2007 "regime-adaptive risk control") is plausible but on this 12-mo Cut 3 it cost money.

**Verdict:** the modification works as designed; the design is wrong for this regime. Revert from default-on, but the toggle is fine to keep for future regime-conditional use.
